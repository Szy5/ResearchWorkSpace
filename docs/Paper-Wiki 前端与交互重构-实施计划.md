# Paper-Wiki 前端与交互重构实施计划

日期：2026-11-03  
状态：首期 P0 已实现并验证；后续阶段保留为未实现规划。  
依据：Parallax 公开页面调研、本地首页与阅读页实际查看、当前前端与接口代码检查。

## 1. 目标与首期范围

将 Paper-Wiki 改善为以阅读为中心的个人研究工作台，让用户清楚知道：当前在哪、可以做什么、操作是否成功、下一步是什么，以及离开后如何继续。

视觉与交互共同验收。首期覆盖发现、论文库、阅读/编辑/核验、任务面板，以及现有公众号发布流程的衔接。

- 保留已有检索、推荐、批量生成、任务持久化、人工审查和公众号草稿能力。
- 以现有 React / FastAPI 和文件资产为基础，按页面逐步替换，避免整套推倒重写。
- 不扩展知识图谱、向量检索或通用研究 Agent；不创建新的 Layer 2/3 阶段。
- 专题集合、收藏/已读模型、多篇对比、定时跟踪属于后续增量，不在首期展示不可用入口。
- 原始论文资产保持只读；布局处理不修改笔记正文或审查状态。

## 2. 已确认的问题与约束

| 问题 | 证据与影响 | 首期处理方向 |
| --- | --- | --- |
| 阅读区域受到挤压 | 本地 1440px 页面中正文与辅助区域上下排列，标题重复、工具栏占据首屏 | 阅读优先布局，辅助信息按需展开 |
| 视觉元素竞争 | 深色侧栏、蓝色强调、网格背景、卡片阴影并存 | 统一低干扰视觉层级 |
| 连续选论文被打断 | `App.tsx` 在暂存数量增加时自动打开遮罩任务面板；`Home.tsx` 将已选论文从结果中移除 | 推荐改为原位标记、轻提示、批量操作条，用户主动打开任务面板 |
| 返回后缺少上下文 | 页面和选中论文主要由组件状态管理；首页卸载后检索结果丢失 | 页面链接、搜索快照、筛选与滚动恢复 |
| 编辑缺乏离开保护 | `PaperDetail.tsx` 切论文会重新加载草稿，未见脏状态离开拦截 | 草稿保护、保存结果反馈、冲突恢复 |
| 保存与核验含义混合 | 元信息保存调用同时设置核验标记，前作保存后也标记核验 | 明确区分保存内容和人工确认；检查现有接口能否完整支持 |
| 推荐状态容易误解 | 调研时“今日推荐”为 2026-10-27 快照，并处于排序降级 | 显示真实日期、时效和排序状态 |
| 缩略图可能误导 | `CandidateCard.tsx` 通过哈希从固定图库选图 | 使用真实资产；没有真实图片则使用文字布局 |
| 任务完成缺少后续动作 | 任务面板主要展示状态、日志与清除 | 成功可打开结果，失败可定位原因与受控重试 |

已有批量任务跨页与刷新恢复机制应保留。浏览器刷新恢复展示与后端重启恢复执行不是同一能力：后端中断任务应如实显示失败，不宣称自动续跑。

原位保留已选卡片是对旧版“移到暂存区”交互的调整建议，需要在原型评审时重点确认；本计划不直接改变现有行为。

## 3. 核心用户路径与交互约定

### 3.1 发现 → 查看候选 → 批量生成

1. 搜索区域明确当前搜索范围，arXiv 搜索与本地论文搜索不混用。
2. 支持关键词检索及 arXiv ID/链接识别；识别失败时解释格式，不静默提交错误请求。
3. 候选标题用于打开详情预览；复选框用于多选，两种动作分开。
4. 勾选后保持列表位置，显示“已选 N 篇”操作条，支持取消选择；不自动弹出遮罩。
5. 点击“生成精读”才提交任务，明确数量与产物范围；重复点击不会重复提交同一批任务。
6. 提交后保持用户当前阅读/浏览位置，用任务入口数量与轻提示反馈。
7. 已入库、已选、生成中、生成失败分别展示；重复检索命中已入库论文时提供“打开论文”。

搜索区分首次加载、更新中、空结果、失败、展示上次结果。新搜索失败时可以保留旧结果，但必须标注其对应查询。处理请求先后顺序，避免旧响应覆盖新结果。年份范围有效性在提交前校验，默认结束年份不硬编码。

### 3.2 论文库 → 阅读 → 返回

1. 论文库提供列表、搜索和快捷筛选；待核验作为同一论文库的快捷视图。
2. 打开论文后默认进入阅读态，正文占主要空间；列表和辅助栏可收起。
3. 返回时恢复搜索词、筛选、列表滚动和选中论文；刷新能回到同一篇论文。
4. 提供阅读目录与专注模式，恢复每篇论文的位置；正文版本变化时安全回退到对应章节或顶部。
5. 页面链接无效或论文不存在时，提供返回论文库的明确动作。
6. 快速切换论文时，标题、正文和操作对象必须一致；加载中不允许对上一篇执行误操作。

首期可用浏览器本地存储记录阅读位置与布局偏好；正式“待读/已读/收藏”记录留待后续数据模型设计，不能用 `reviewed` 代替。

### 3.3 阅读 → 编辑 → 核验

1. 阅读、编辑、核验入口清晰分开；默认阅读态不展示全部编辑控件。
2. 编辑时显示未保存状态、保存与取消；保存成功后明确反馈，失败则保留输入。
3. 有未保存内容时，切换论文或离开页面提供“保存并离开 / 放弃修改 / 继续编辑”；刷新和关闭页面使用浏览器支持的离开提醒。
4. 保留现有乐观锁。版本冲突时不直接覆盖，保留当前草稿并提供重新加载/复制草稿的恢复路径。
5. 明确保存与人工核验的不同含义；元信息与前作两个核验项保持独立，整体状态继续遵循现有规则。
6. 重新生成会影响已编辑内容时，先说明覆盖范围；任务失败保留可用旧内容。实现前核实后端写入行为，必要时补充最小保护。
7. 隐藏重复标题只发生在展示层，不改写 `summary.md`。

首期“核验”继续使用已有摘要与前作能力；原文双栏、章节证据定位作为后续阅读增强，不伪装成已具备的逐句引用能力。

### 3.4 后台任务 → 查看结果或恢复失败

1. 选中待生成、排队、运行、成功、失败在界面上区分，不能把选中状态当成任务已提交。
2. 提交请求失败时退出提交中状态、保留选择并给出重试入口。
3. 部分失败按论文展示，允许只重试失败项；成功项不随重试再次生成。
4. 只有具备明确输入参数与安全重试路径的任务才提供重试。首期优先覆盖精读生成；公众号草稿创建不通用自动重试，结果不明确时先核对已有草稿。
5. 刷新后从后端同步任务状态；轮询断网不直接等同任务失败，恢复连接后重新查询。
6. 成功提供“打开精读/查看结果”；查看后返回保留原上下文。
7. 清除提示、移除待生成项、取消运行任务是不同操作。无取消接口时不显示可取消按钮。
8. 任务抽屉支持 Esc、合理初始焦点、焦点约束和关闭后焦点返回；关闭面板不停止任务。

### 3.5 阅读 → 写作与发布 → 返回

1. 从论文进入现有发布工作台，保留来源论文与返回入口。
2. 标题、摘要、封面、排版可预览，陈旧预览与准备失败明确显示。
3. 创建公众号草稿由用户明确触发，提交中防止重复点击。
4. 成功文案明确为“已创建公众号草稿”，不称为“文章已发布”。
5. 已有发布能力继续复用；首期不扩展渠道或改变其外部写入边界。

## 4. 视觉与响应式规范

- 暖白主背景、浅灰导航、深灰正文、单一低饱和强调色；减少背景装饰和大面积阴影。
- 统一按钮主次、表单、标签、提示、加载骨架和空状态；状态同时用文字表达。
- 中文操作文案统一，避免工程词及无必要的中英混用。
- 字体分别考虑中文正文、英文论文标题、界面控件；正文目标宽度约 720–820px，空间不足时优先收起辅助面板。
- 以可用内容宽度决定列数，避免只依赖浏览器宽度导致正文被挤压。
- 1280/1440px 桌面重点验收；1024px 及 390px 窄屏保证任务可完成，采用列表/详情切换而非强制多栏。
- 长标题、长作者列表、公式、宽表格、图片缺失均使用真实数据验证；宽表格仅在自身区域横向滚动。
- 主操作支持键盘，焦点可见，按钮名称可读；提示不能仅靠颜色，动画尊重减少动态效果偏好。

## 5. 实施步骤与交付

首期已按下列依赖顺序完成。交互与视觉以本计划及实际可操作页面交付，未另建静态原型；页面已进行真实内容与多尺寸走查。

| 阶段 | 任务 | 交付物与完成条件 |
| --- | --- | --- |
| P0-1 交互定稿 | 画出五条核心用户路径；梳理每个动作的加载、成功、失败、返回状态；确认卡片选择和审查语义 | 交互流程、状态表、发现与阅读页低保真原型 |
| P0-2 视觉原型 | 用真实内容制作发现页、论文库、阅读页；补充任务抽屉与编辑离开场景 | 高保真原型、基础设计规范；同时评审点击过程与外观 |
| P0-3 应用框架 | 建立可恢复的页面链接/查询状态、导航、阅读布局及基础组件 | 刷新、前进、后退和窄屏导航通过；链接实现适配现有静态托管 |
| P0-4 发现与任务 | 调整候选预览/多选/批量提交，推荐时效与降级提示，真实缩略图策略，任务结果与重试 | 连续选多篇不被遮罩打断；部分失败可以恢复；旧任务状态兼容 |
| P0-5 阅读与核验 | 阅读布局、目录、位置恢复、编辑保护、保存/核验分离、覆盖提示 | 长文可舒适阅读；离开与保存失败不静默丢失输入 |
| P0-6 发布衔接与验收 | 统一现有发布和管理页视觉，完善返回与提交反馈；执行关键流程回归 | 发现到公众号草稿路径完整，文档与现状一致 |

发现页与阅读页在 P0-2 提供可评审原型，作为正式实现前的设计检查点；避免所有页面实现完才发现交互方向不合适。

工程工作主要集中于 `App.tsx`、`Home.tsx`、`Dashboard.tsx`、`PaperDetail.tsx`、`ActivityDrawer.tsx`、候选卡片与任务 hooks、共享样式及现有发布页面。先核实已有接口契约；必要的保存/核验与任务恢复修正限定在现有 Web 能力内。

## 6. 首期验收场景

- [x] 搜索后连续选择 5 篇论文，列表不突然跳动、遮罩不打断选择；可逐项取消。
- [x] 批量提交后切到论文库并刷新，任务状态仍可查询；成功项能直接打开结果。
- [x] 批次中部分失败，只重试失败项，不重复生成成功论文。
- [x] 断网、接口失败、空结果、过期推荐、排序降级都有准确说明与下一步动作。
- [x] 从筛选结果打开论文、阅读中段再返回，筛选和位置保留；浏览器前进/后退行为一致。
- [x] 快速连续切论文，不出现 A 标题配 B 正文、或操作落到错误论文。
- [x] 修改笔记后离开触发保护；保存失败、版本冲突均保留草稿；普通保存不默认为人工核验。
- [x] 1440px 与 1280px 阅读布局不被发布/前作面板挤成小窗口；窄屏可单独进入详情和返回。
- [x] 原始文档与既有人工核验记录不因布局迁移被改写；列表刷新不会自动核验内容。
- [x] 从论文进入发布、预览、创建草稿及返回流程正常；失败和不确定结果不会诱导重复创建。
- [x] 键盘可完成搜索、多选、打开/关闭任务面板及保存；焦点位置合理。

验证采用现有前端测试、构建检查和真实页面走查。新增测试集中在状态恢复、异步响应顺序、草稿保护、提交去重与失败恢复等行为；外部 LLM/微信调用使用 mock，验收不真实创建草稿或消耗模型额度。

## 7. 后续阶段与文档维护

首期完成后再规划：持久化收藏/待读/已读、原文对照、轻量专题集合；随后评估研究问题检索、多篇对比和定时跟踪。每项分别定义存储位置、兼容方式、证据来源和范围，不把收藏/阅读进度混入人工审查字段。

实施时同步更新 `README.md`、`docs/项目-需求文档.md`、`docs/Paper-Wiki 技术方案_v1.md`，以及受影响的推荐/首页交互说明；资产契约变化才更新 `docs/Paper2Assets-设计方案.md`。AGENTS 中提及的部分旧文档名称当前不存在，应核实沿革后维护现有文档，避免另建重复的需求或设计事实来源。

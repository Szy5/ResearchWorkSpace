01

PART

研究动机

MOTIVATION · 为何需要 SSP

近年来基于大模型的Agent（尤其是以搜索为核心工具的深度搜索代理）在复杂信息检索与多步决策场景中表现突出，但其训练仍高度依赖人工构造的、可验证的问答对以提供精确奖励（即 RLVR）。

构建大量高质量、可验证的任务对需要大量人工验证，限制了 agentic 强化学习的规模化。现有的自动合成查询方法要么离线、要么难以动态控制难度，因而难以形成自我持续训练的闭环。

本文提出将自我对弈（self-play）引入深度搜索场景，令同一 LLM 同时扮演「问题提出者（proposer）」与「问题求解者（solver）」，并用检索增强生成（RAG）验证提出问题的可验证性，从而实现无需人工监督的可扩展训练流程。

02

PART

核心洞见

INSIGHTS · 三句话抓住本质


洞见一 · 可验证任务自生成

让模型同时生成任务与解决任务，并以提出者的检索轨迹作为外部证据，构造「可验证」问题——既保证奖励准确性，又避免人工标注。


洞见二 · 共进化难度调度

提出者与求解者在竞争与合作中共进化：求解者变强时，提出者会生成更难的问题，防止过拟合并推动持续学习。


洞见三 · RAG + 噪声防作弊

加入 RAG 验证与适量噪声文档，能显著提升问题质量，并防止提出者「作弊」（在限定证据下可验证但实际难以求解）。

核心机制

共进化形成对抗式课程，比静态合成数据更省心

提出的方法

METHOD · SSP 怎么跑起来

方法概述

SSP（Search Self-play）的核心流程包含两条并行角色轨迹：提出者使用多轮搜索调用来发掘证据并形成带有明确答案的深度搜索问题；随后收集提出者检索到的所有文档作为RAG 上下文，供求解者在不再调用搜索的情况下验证并回答问题；验证通过的问题被用于RL训练回路，从而对提出者和求解者分别提供奖励与更新。

这个闭环保证了问题的可验证性和训练数据的自洽性。

双方共进化

SSP 闭环：自生成任务 → 可验证奖励 → RL 更新

— 方法概览：提出者搜索挖证据并生成问题，求解者用其文档做 RAG 验证与求解

关键组成

提出者（proposer）：基于策略网络，用 REINFORCE 优化，目标是生成难度递增且证据充分的问题；过程中最多 10 轮工具（搜索）调用。

求解者（solver）：多轮推理与工具调用回答问题，用 GRPO 更新；RAG 验证阶段仅基于提出者轨迹提供的检索文档生成，检验答案是否可复现。

RAG 验证：取提出者轨迹中检索到的 top-3 文档（本地 E5，Wiki-2018）作为上下文；注入数量为 k 的噪声文档（同批次其他轨迹）。实验证明 k=4 时效果最佳。

奖励与对弈规则：以「是否与 ground-truth 等价」的二元奖励为核心（RLVR 思路），并通过两者交替对弈来调节难度与训练信号。

实验结果

EXPERIMENTS · 数字说话

实验设置

基准：在 NQ、TriviaQA、PopQA、HotpotQA、2WikiMultiHopQA、Musique、Bamboogle 七个常用 QA 基准上评估；每个基准随机抽样 500 个 QA（Bamboogle 用 125 个）。

模型与对比：Qwen2.5（7B/32B）、LLaMA3.1、Qwen3，以及 Search-R1、ZeroSearch、R-Search 等搜索专门模型。工具限制：本地 E5 检索 top-3，搜索调用上限 10 轮；评估用 Qwen2.5-32B-Instruct 作 judge，度量 pass@1（100 分制）。

消融研究

固定对手 vs 共演化：与仅训练求解者（Solver-Only）或仅训练提出者（Proposer-Only）相比，完整 SSP 共进化框架表现最好。

仅训练求解者会出现内在训练奖励快速饱和（≈0.9），导致 held-out 集过拟合并退化；仅训练提出者则难以生成对复杂多跳任务有推动作用的问题。

去掉 RAG 验证会显著降低性能（尤其 GeneralQA）。噪声文档实验显示：适度噪声（4 个）最佳，过多（7）会使验证混淆、性能下降。

— 训练动态与 ablation：in-game reward 与 NQ、2Wiki eval 曲线，支持共演化优势

05

PART

分析与洞察

ANALYSIS · 为什么有效


对抗式课程

SSP 内在形成的 adversarial curriculum 是低成本、在线自适应的难度调节机制。训练曲线中求解者成功率的短暂下降，正是提出者提升难度的直接证据。


RAG + 噪声 = 防作弊护栏

保证奖励精度的同时，约束提出者避免生成「在给定小集合中显而易见、但实际不可检索」的作弊题，提升泛化性。


突破内部知识局限

提出者利用外部检索，理论上可接入任意检索语料与工具，扩展到法律、科研等需可溯源证据的域。

！ 稳定性风险

提出者若过度追求「难度」可能生成不合逻辑或不稳定的问题；RAG 与噪声是防护，但仍需精细调奖励与策略，避免「毒样本」进入训练集。

主要贡献

CONTRIBUTIONS · 带走三点

1

提出并实现 Search Self-play (SSP)：首个将 self-play 与检索增强结合、用于 agentic 搜索训练的端到端方案，无监督生成可验证任务并共同提升提出与求解能力。

2

设计基于提出者检索轨迹的RAG 验证机制与噪声注入策略，保证问题质量并防止提出者作弊。

3

在多模型、多基准与多训练范式上展示显著且稳定的提升（含从零训练与持续训练），并以系统消融证明共演化的必要性。

07

PART

局限性与未来工作

LIMITATIONS · 还差什么

语料与检索依赖：当前以 Wiki-2018 + 本地 E5 为主；在专利、医学等稀缺语料上的表现尚需验证，检索器质量会直接影响问题质量。

验证器与判分偏差：LLM-as-a-judge 存在评判噪声；需要更多人类对齐或更稳健的自动判分，减少误判对训练的影响。

更高级的作弊策略：噪声能限制某类作弊，但提出者仍可能学会更隐蔽的「坑位式」提问；未来可引入更严格的逻辑一致性检查或外部证据链验证。

可解释与可追溯：如何把检索轨迹包装成可审计的证据链，以满足高敏感性领域应用，是后续重要方向。

SUMMARY · 一句话带走

Search Self-play (SSP) 提供了一条可扩展的无监督 agentic 训练路线：通过提出者与求解者的共演化、自带检索证据的 RAG 验证，以及噪声注入的对抗式约束，在多模型、多数据集和不同训练范式下均带来稳定且显著的性能提升。

此方法既缓解了 agentic RL 中对人工可验证数据的依赖，也为未来将自监督自适应课程与工具驱动的 LLM Agent 训练结合提供了实证基础。

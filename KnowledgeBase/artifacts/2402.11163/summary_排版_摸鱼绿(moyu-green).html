01

PART

研究动机与贡献

MOTIVATION · WHY KG-AGENT

为什么要把大模型和知识图谱（KG）结合？


LLM 的短板

现代 大语言模型（LLMs） 在语言理解上很强，但在多跳、知识密集型推理上依赖内参知识并不稳定。知识图谱以三元组存储结构化事实，可作外部知识来源，但如何高效、灵活地让 LLM 利用 KG 仍是挑战。


现有路线的局限

现有方法主要有两类：检索增强（把相关三元组序列化进 prompt）和 协同增强（设计 LLM 与 KG 的交互策略）。问题在于：交互策略常是人工预设，难适应复杂任务；且许多方法依赖封闭大模型 API，不利于开放小模型的实用化。

三大核心贡献

1

提出 KG-Agent：基于 LLM 的自主代理框架，让较小模型在推理中主动决策、反复调用工具直至完成 KG 推理，减少对更大闭源模型的依赖。

2

构建面向 KG 的多功能工具箱，把筛选、计数、检索等图操作封装为可调用工具，使模型以离散、可执行的方式操纵结构化结果。

3

用程序化指令合成把 KGQA 推理链转为可执行程序与指令对，约 10K 样本微调 LLaMA-7B，显著提升域内与域外表现。

PART

方法介绍

METHOD · AGENT LOOP

总体思路：把经过指令微调的 LLM、多功能工具箱、基于 KG 的执行器与记忆模块组成闭环代理。模型循环选择工具、交执行器运行、把结果写入记忆，并以此决定下一步，直到输出最终答案或 SPARQL 查询。

— 图：KG-Agent 概览（上半部为代理运行流程，下半部展示指令微调数据合成与 prompt 模板示例）

关键组件

多功能工具箱（Toolbox）

把 KG 推理中常见操作封装为工具，例如基于 SPARQL 的检索、集合运算（交并补）、聚合（计数、排序、Top-k）等。接口明确、离散，便于 LLM 学会何时调用何种操作。

KG 执行器

接收工具调用生成的查询或指令（例如 SPARQL），在实际 KG 上执行并返回结构化结果，避免把大量原始三元组直接拼进 prompt。

知识记忆（Memory）

记录中间实体集、推理步骤、上下文提示等，支持短期迭代决策与长期检索线索。每一轮 LLM 可读记忆并决定下一工具调用或终止。

自主迭代机制

通过读问题 + 读记忆来选择工具（或直接输出答案），形成「感知—行动—观察—记忆更新」环路；本工作以监督学习与工具调用行为为主导。

程序化指令合成与微调

从现有 KGQA 数据抽取推理链，生成等价程序，再构造「问题 → 代码式推理步骤 → 工具调用样例」指令对，对 LLaMA-7B 微调以习得操纵结构化数据的能力。

简化代理循环

STEP 01

读入

LLM 读取问题与记忆。

STEP 02

选工具

选择工具（如 query_entities、filter_by_relation、count）。

STEP 03

执行

生成工具调用指令 → 执行器执行 → 返回结构化结果。

STEP 04

写记忆

更新记忆，记录新实体集与步骤。

STEP 05

终止判定

若满足终止条件则输出答案，否则回到步骤 1。

感知

问题 + 记忆

→

行动

选工具并执行

→

记忆更新

写回再迭代

自主决策环路：比固定交互策略更灵活

实验结果

RESULTS · 10K SAMPLES

评测任务与数据集


域内 KGQA

CWQ、GrailQA、WebQSP 等（多跳、复杂查询）。


域外 / 零-shot ODQA

WQ-Freebase、TQ-Wiki 等，用于测试迁移与泛化能力。

主要结果亮点

仅用约 10K 合成指令样本微调 LLaMA-7B 后，KG-Agent 在多项数据集上超越了以更大 LLM 或更多训练数据为基础的现有方法。

CWQ

约 +7.5% 相对 F1

GrailQA

约 +2.7% 相对提升

TQ-Wiki

约 +8.5% 相对准确率

域外零-shot 性能优于一些使用全量监督微调的模型；数据量敏感性 方面，性能随微调样本量增长快速上升，但在 10K 左右已达很好效果，体现了「程序化合成指令 + 工具化接口」对小模型的高效性。

实证结论

以工具化、程序化的训练数据指导，较小模型也能学会在 KG 上进行多步、结构化推理。自主代理式的工具选择与记忆更新，使推理流程更灵活，可适应未预见的任务需求。

简要总结

SUMMARY · TAKEAWAYS

要点回顾

KG-Agent 将 LLM、工具箱、KG 执行器与记忆结合成自主代理，允许模型在 KG 上反复做工具选择和记忆更新，直至完成推理任务。

使用程序化指令合成，对 LLaMA-7B 进行约 10K 样本微调，就能在多个 KGQA 与 ODQA 任务上取得或超过现有 SOTA，显示了小模型通过「学会操纵结构化数据」获得的效率优势。

框架强调模块化（工具 / 执行器 / 记忆）与可解释的中间结果（可审计的工具调用与执行器返回），对实际应用友好。

局限与未来方向


合成质量依赖

当前依赖高质量程序合成——合成质量会影响微调效果；如何自动获得更广泛、鲁棒的合成数据是下一步工作。


结构化数据扩展

目前侧重 KG（图结构）；作者计划将框架推广到其他结构化数据（关系型数据库、表格等）。


工程与稳健性

实际应用中的延迟与执行器开销，以及在开放域 KG（长期更新、噪声事实）上的稳健性仍需评估。

如果你只记三点

① 工具 + 记忆 + 程序化指令微调，让小模型能做复杂 KG 推理

② 10K 合成样本即可显著提升 LLaMA-7B 的多跳 KGQA 能力

③ 代理式自主决策比固定交互策略更灵活，更易推广

阅读原文可进一步了解工具集合的具体接口、程序合成细节和完整实验表格与消融研究。

先前工作分析

PRIOR WORK

近年工作在三个技术方向上为 KG-Agent 提供了直接构建模块与问题意识：


协同交互方法

以 StructGPT 为代表，把 LLM 的语言理解与对 KG 的结构化查询结合起来，通过多轮交互或 SPARQL grounding 完成多跳问答。


语言代理范式

如 ReAct、AutoGPT、ProgPrompt，把 chain-of-thought 与显式 action / 工具调用、程序化 prompt，以及短 / 长期记忆结合起来，实现自动化的工具选择、执行与记忆管理。


检索增强与记忆

RNG-KBQA / TIARA 等暴露了检索式丢失结构信息的局限；MemoryBank 则提示需要有效的记忆策略。

两相结合，浮现两方面机会：一是需要能自主选择工具、执行 KG 操作并在多步之间维护中间知识的代理框架；二是需要用可执行的程序化表示训练较小 LLM，使其可靠生成可执行操作序列。KG-Agent 正是在此背景下成为自然下一步：综合代理式工具调用与记忆管理、以代码 / 程序化指令微调 LLM，并针对 StructGPT 与检索式方法的局限设计自适应迭代决策与 KG 执行器，从而使较小模型也能高效完成复杂 KG 推理。
